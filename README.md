# 通信基站运维管理平台

面向通信基站站点入网、动力环境监控、天馈巡检、发电保障与退网拆站的一体化基站运维管理后台。

这是一个前后端分离的管理平台：前端 Vue 3 + Vite + TypeScript，后端 FastAPI（Python）。
两边各自独立启动，前端 dev server 已关掉自动打开页面，启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/              统一请求封装
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false）
├── backend/                  FastAPI（Python） 后端
│   ├── app/routers/          每个业务模块一组接口
│   ├── app/services/         业务规则与状态流转
│   └── app/store.py          内存数据仓库与示例数据
├── .gitignore
└── docker-compose.yml
```

## 启动

### 后端

```bash
cd backend
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
./run.sh
```

健康检查：`curl http://127.0.0.1:8000/api/health`

### 前端

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，
需要自己访问。`/api` 由 vite 代理到后端 `http://127.0.0.1:8000`。

## 电磁环境备案（emr）

把原先各存各的环评备案与辐射监测收成一份对得上的档案，关键规则都在
`backend/app/services/emr.py`：

- **监测点位**：按「监测点编号 + 所属站点」登记功率密度（W/m²）、监测日期、天线轮次。
  合格与否由服务端按**监测当时生效的限值版本**裁定，前端传“合格”不生效——越线一律记不合格；
  同一点位复测覆盖原记录，不造重复档案。
- **备案文书状态机**：待提交 → 已受理 → 已备案 → 已失效。材料不齐不予受理；被退回的档案
  补交时只补缺的那几份，已交过的材料保留且会明确告知“无需再交”。存在越线监测点位的站点，
  受理环节直接打回整改，不允许出具备案合格结论。
- **限值换版**：发布新版本后，全部存量站点按新版重算“现行符合性”；监测留档判定与
  “留档结论/留档依据版本”锁定监测、备案当时那一版，不随换版改变。
- **结论单一事实源**：每份档案只有一个 `conclusion` 对象。站点台账的“电磁合规栏”
  （`/api/site`）、备案详情页、按站点编号的外部入口（`/api/emr/sites/{站点编号}/conclusion`）
  读的都是同一份；刷新页面、退出再进来结果一致。内存态数据随后端重启重置。
- **授权**：演示账号 `envadmin`（环保归口管理员，持全部授权）、`ops`（运维人员，无写授权）、
  `viewer`（只读访客）。出具/更正备案结论（`emr:conclusion:edit`）、审查受理（`emr:review`）、
  限值换版（`emr:limit:publish`）只有环保归口管理员可执行；越权一律 403 打回，
  提示中写明缺少的授权项名称与编码。

端到端用例（需先起后端）：

```bash
cd backend
python3 tests/emr_e2e.py
```

## 约定

- 每个模块的前端页面在 `frontend/src/views/<模块>/index.vue`，后端接口在
  `backend/app/routers/<模块>.py`，业务规则在 `backend/app/services/<模块>.py`。
- 列表接口统一返回 `{ items, total, page, size }`，动作接口统一返回 `{ ok, message }`。
- 状态流转只允许在 `app/services` 里改，路由层不做业务判断。
